# SCR: DeepSeek V4 Native Reasoning Modes

## Requested Behavior
- For `DeepSeek-V4-Flash-0731`, expose only `off`, `low`, `high`, and `max` across both LiteLLM deployments, the `opencode-litellm` plugin, OpenCode, and Codex on this host.
- Reject `medium` and `xhigh` for this model instead of silently translating them.
- Translate `off` to the upstream non-thinking control and pass `low`, `high`, and `max` as exact native `reasoning_effort` values.
- Generate OpenCode model variants from `opencode-litellm`; do not maintain a conflicting manual DeepSeek variant list in OpenCode.

## Acceptance Intent
- Both LiteLLM proxies reject `medium` and `xhigh` before forwarding to vLLM.
- Both LiteLLM proxies accept and correctly forward `off`, `low`, `high`, and `max`.
- `opencode-litellm` publishes exactly those four DeepSeek variants with the correct payload mapping.
- Local OpenCode consumes the generated variants without conflicting overrides.
- Local Codex offers or uses only the four supported modes for this model and sends the correct upstream controls.
- Existing reasoning behavior for unrelated models remains unchanged.

## Approval
Approved directly by the user on 2026-08-25.

## Clarification - Client Adapter Normalization
- The visible/user-selectable mode remains `off`.
- `opencode-litellm` may serialize semantic `off` as wire `reasoning_effort=none` because OpenCode uses one variant body as the request payload.
- LiteLLM must still accept public API `off` and normalize it for direct callers.
- This clarification does not expose `none`, `medium`, or `xhigh` as selectable modes.

## Scope Override - Client-Owned Validation
- Per user direction on 2026-08-26, LiteLLM does not need to restrict or reject incorrect reasoning values for this model.
- Enforcement is client-owned: OpenCode and Codex must expose only the approved modes and serialize them correctly.
- Remove or do not deploy the task-owned model-specific LiteLLM validation policy; retain normal generic LiteLLM/vLLM pass-through behavior.
- The deployed client contract remains visible `off`, `low`, `high`, `max`, with client-side `off -> none` where required by the wire protocol.

## Scope Override - Official OpenCode Only
- Per explicit user correction on 2026-08-26, never replace, patch, or locally build the OpenCode binary/core for this work.
- Restore and retain the official OpenCode installation.
- OpenCode behavior may be changed only through configuration generated by `opencode-litellm`; manual model overrides are not desired.
- If official OpenCode intrinsically shows a default sentinel, do not patch core to hide it; ensure only the plugin-generated named effort levels are correct.

## Scope Override - Published Plugin Only
- Per explicit user direction on 2026-08-26, Syncthing-shared OpenCode configuration must never reference a local `file://` plugin artifact.
- Publish the reviewed plugin to npm using the repository-local protected npm credential source, without disclosing or committing it.
- Active `opencode.json` must pin the published npm package version.
