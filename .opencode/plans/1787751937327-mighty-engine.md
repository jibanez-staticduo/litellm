# Añadir `ox-alpha` a LiteLLM y OpenCode

## Decisiones confirmadas

- Configurar únicamente el LiteLLM del NAS
- Exponer el alias `ox-alpha` con upstream `openrouter/stealth/ox-alpha`
- OpenCode lo consumirá exclusivamente como `LiteLLM/ox-alpha`
- PostgreSQL es la fuente de verdad; no modificar archivos de LiteLLM ni del repositorio
- Usar LazyMCP y `litellm_admin` para consultar y administrar el despliegue
- Recuperar la clave del item `openroute` mediante el MCP de 1Password sin mostrarla
- No ejecutar inferencias

## Estado verificado

- `litellm_admin-health` confirma servicio saludable y PostgreSQL conectado
- `litellm_admin-list_models` y `GET /model/info` muestran 32 deployments; no existe `ox-alpha` ni un upstream OpenRouter
- `litellm_admin-list_credentials` muestra una sola credencial no relacionada; no existe una credencial OpenRouter
- `GET /router/settings` no define aliases ni fallbacks adicionales
- OpenCode usa el plugin `@staticeng/opencode-litellm`, que descubre modelos dinámicamente desde `https://litellm.staticduo.com/v1`

## Implementación

1. Consultar el MCP de 1Password para localizar el item `openroute`, identificar de forma segura su campo de API key y recuperar el valor únicamente en memoria. No incluir el valor en mensajes, logs, archivos o evidencias
2. Volver a consultar `litellm_admin-list_credentials` y `GET /model/info` justo antes de mutar. Si ya existe una credencial OpenRouter o `ox-alpha`, comparar su configuración y detenerse ante cualquier conflicto
3. Crear mediante `litellm_admin-create_credential` una credencial DB-backed con nombre estable `openrouter`, tipo OpenRouter/OpenAI-compatible según el contrato real del endpoint y la clave recuperada. No guardar la clave en `config.yaml`, `.env` ni configuración de OpenCode
4. Crear mediante `litellm_admin-add_model` un único deployment con `model_name: ox-alpha`, `litellm_params.model: openrouter/stealth/ox-alpha` y referencia a la credencial `openrouter`. Añadir solo metadata de capacidades que LiteLLM/OpenRouter proporcionen de forma verificable; no inventar límites, costes o modalidades
5. No modificar `/home/staticduo/.config/opencode/opencode.json` inicialmente. Reiniciar OpenCode después del alta para que el plugin recargue el catálogo. Solo considerar un override mínimo si el modelo no aparece o su metadata impide seleccionarlo; no configurar acceso directo a OpenRouter

## Idempotencia y rollback

- Si la credencial o el modelo ya existen y coinciden, no realizar cambios
- Si existen con otra definición o hay duplicados, detenerse y pedir confirmación
- Registrar los identificadores creados durante la operación

- Si la validación posterior falla, eliminar únicamente el deployment creado y después la credencial creada, usando sus herramientas administrativas específicas
- No tocar Fedora, archivos de configuración, otros deployments, aliases ni fallbacks
